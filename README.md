# OPC 智能膳食顾问（AI Smart Nutrition Advisor）

> 赛题：OPC 第二届实战能力大赛 · 软件与智能体开发赛道
> 项目：AI 智能膳食顾问（HealthPick 顾问版）｜目标等级 **A 级**

---

## 一、系统简介

本系统是一个面向 25-45 岁都市白领的 **AI 智能膳食顾问 Web 应用**，能够：
- 识别用户健康诉求（减脂塑形 / 增肌强化 / 慢病调理 / 控压调理）；
- 从营养知识库推荐匹配的膳食方案与食材组合，并说明推荐理由；
- 基于平台提供的营养资料准确回答食材营养、膳食搭配、饮食禁忌等问题，并标注信息来源；
- 支持多轮对话与上下文记忆、用户会话历史持久化；
- 识别饮食禁忌（糖尿病 / 高尿酸 / 海鲜过敏等）并给出安全提示与免责声明。

知识库严格按赛题分类挂载：**素材 A《2026秋季健康膳食指南》+ 素材 B《个性化饮食计划方案》= 核心营养知识库**；**素材 C《健康优选平台服务白皮书》= 辅助平台资料**（仅回答平台/会员/企业合作类问题，绝不参与营养建议，从机制上杜绝混淆编造）。

## 二、如何访问与使用

### 方式一：本地一键运行（进阶需求4 替代方案，评审 15 分钟内可交互）
```bash
# 后端
cd backend
pip install -r requirements.txt
python kb/build_kb.py        # 构建双索引（首次）
python app.py                # 启动 http://localhost:8000
# 前端（另开终端）
cd frontend
npm install
npm run dev                  # http://localhost:5173 （开发模式，/api 自动代理到后端）
# 或构建后由后端统一托管：
npm run build                # 生成 dist，访问 http://localhost:8000
```
- 演示链接（公网部署时）：由自有服务器 Nginx 反代提供 `https://diet.yourdomain.com`（详见 `deploy/nginx-diet.conf`）。
- 二维码 / 公网 URL 二选一即可满足"可运行系统"。

### 使用步骤
1. 打开页面，看到欢迎语与三个快捷入口（减脂 / 增肌 / 血糖偏高）。
2. 点击快捷入口，或直接输入健康问题（如"减脂期晚餐吃什么？""鸡胸肉热量多少？"）。
3. 顾问返回答案，底部标注**来源**（文档名+章节）与**生成模型**；涉及疾病自动附加免责声明。
4. 左侧会话栏可新建 / 切换 / 删除对话，历史自动持久化。

## 三、技术选型与核心逻辑（≥200 字）

- **后端**：Python FastAPI，异步、自带 Swagger，工程性展示强。
- **检索**：BM25（bigram 中文分词）双索引 —— `idx_nutrition`(A+B) 与 `idx_platform`(C) 为**两个物理隔离的检索器实例**，意图路由在检索前决定走哪个库，从机制上杜绝 A/B 与 C 混淆。
- **生成（Agent + Skills 架构）**：采用 **LLM Agent + function calling** 编排范式。后端将"查营养库 / 查平台库 / 推荐方案 / 查禁忌 / 查人群"封装为 5 个 **skills 工具**（`services/skills.py`），LLM 通过工具调用**自主决定调用哪些技能、按什么顺序调用**，再基于工具返回结果生成最终答复（零硬编码，进阶需求2）。无任何工具被调用或缺失 API Key 时，降级为原 RAG"检索直出"模板，仍带来源标注与免责声明，保证可运行。
- **存储**：SQLite 存 users / conversations / messages，满足多轮对话与历史持久化（进阶需求3）。
- **前端**：React 18 + Vite，响应式（桌面/移动自适应），含快捷卡、会话侧栏、加载反馈、三句错误提示。

## 四、系统架构说明（≥300 字）

系统分四层：

1. **数据层**：SQLite 三表。用户表（id/昵称）、会话表（id/用户/标题/更新时间）、消息表（会话/角色/内容/来源）。对话落盘，刷新或换端（同 user_id）可恢复。

2. **知识层**：`kb/build_kb.py` 解析三份 PDF，按"章/节"切分为知识块，每块携带 `{doc, doc_name, chapter, section, text}` 元数据。A+B 合并入营养索引、C 入平台索引，**两个 BM25 检索器代码层不可互访**。

3. **智能体层（Agent + Skills）**：`services/agent.py` 为 Agent 编排核心。对话入口完成意图分类后，交由 Agent 处理：Agent 将用户问题 + 最近 10 轮历史 + 用户画像（人群/禁忌）组装为 Prompt，并把 5 个 skills 以 function-calling 工具规格暴露给 LLM。LLM **先规划要调用的技能**（如"鸡胸肉"→`search_nutrition`、"会员价"→`search_platform`、"糖尿病"→`search_nutrition`+`recommend_plan`），工具内部完成双索引检索/规则计算后回传，Agent 循环最多 5 轮直至收集齐信息再生成答复。双索引物理隔离在 tool 内部强制执行，LLM 无法直接跨库。最终答复经 `_backfill` 后处理，仅做**来源校验 + 免责声明兜底 + 禁忌就医提示**，不强制拒答以保留 LLM 动态答案。无 Key 时整体降级为原 RAG 流程。

4. **应用层**：FastAPI 提供 `/api/chat`（对话）、`/api/suggest`（快捷推荐）、`/api/sessions`（会话管理）、`/api/history`（历史）、`/api/greeting`（开场白）。核心工作流：入口校验（空/超长）→ 意图路由（营养/平台/无关）→ 营养与平台意图交 Agent 编排 → 无关意图返回功能介绍 → 后处理兜底。

5. **部署层**：前端 Vite 构建产物由后端 `/` 托管，或经 Nginx 反代 + certbot 提供 HTTPS 公网访问；`.env` 管理敏感配置，绝不入库。

**Prompt 设计**：系统角色限定"仅基于知识块作答、禁止编造、必须标注来源、疾病必带免责、严禁用平台价格回答营养问题"，并强约束"必须先调用工具再回答"；用户问题 + 检索块 + 用户画像（人群/禁忌） + 历史摘要组装后调用 LLM。

### 6.1 模块级标注清单

| 模块 | 文件 | 处理方式 | 说明 |
|---|---|---|---|
| 知识库解析 | `backend/kb/build_kb.py` | **AI 生成初版 + 人工校核** | 骨架与 PDF 切块逻辑由 AI 生成；双索引落盘结构、章/节元数据抽取由人工修正校准 |

### 6.2 优化理由

- **AI 辅助价值**：快速搭建项目脚手架（知识库解析脚本、FastAPI 接口模板、React 组件结构、RAG Prompt 初稿、验收测试样例），显著提升开发速度。
- **人工优化关键点**：合规红线（防混淆 / 防编造 / 强制免责）与工程正确性必须人工把关——双索引物理隔离、按意图裁剪工具集、禁忌规则表、来源校验正则、免责声明兜底、部署配置均涉及评审一票否决项，一律由人工设计、复核并标定阈值。
